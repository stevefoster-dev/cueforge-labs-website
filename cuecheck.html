The safe loop

Validate first, deliver second, swap only when complete

Content that fails the spec never reaches a playback machine, and a destination is only updated once the whole target set is ready — so a half-finished delivery cannot become a half-finished show.

  1. 01

    Watch

    Monitor the delivery folder the content team is already using.

  2. 02

    Validate

    Probe each file against the spec profile for its destination.

  3. 03

    Name and stage

    Apply the show's naming convention and hold the file in a controlled staging area.

  4. 04

    Deliver

    Push to the required destinations over the local network and record what landed.

  5. 05

    Swap and report

    Complete the target set, swap atomically, and tell the room what changed.

Capabilities

The part of content delivery nobody wants to own

Catch it early

Spec validation

Every destination gets its own profile, and every arriving file is measured against it instead of against somebody's memory.

  • Probe-driven checks on resolution, codec, frame rate, colour and file size
  • Per-destination spec profiles with inheritance
  • Broad production codec coverage — NotchLC, HAP/HAPQ, DXV3, ProRes, DNxHD/HR, broadcast formats and image sequences
  • Loudness measurement where the profile requires it
  • Rejected and needs-review files are separated rather than silently dropped

Keep names honest

Naming and organisation

Consistent naming is what makes the rest of the pipeline — and the console — predictable.

  • Automatic renaming to the show's convention with prefix enforcement
  • Deliverable identifiers that drive routing and visibility
  • Sequential or date-based versioning
  • Slot ranges, show order and reservations so a slot can be claimed before content arrives

Get it onto the machines

Safe local and LAN delivery

Delivery is explicit, bounded and reversible rather than a background copy nobody is watching.

  • Explicit target sets — a delivery is complete only when every required destination has it
  • Atomic swap so a destination is never left holding a partial file
  • Redundancy-aware pushes, with divergence surfaced when a pair breaks mid-push
  • Scheduled and on-demand sync runs
  • Credentials held in the operating system's keychain, never in plain configuration

Tell the room

Operator visibility

Anyone on the production network can see the state of content without interrupting the operator.

  • Dashboard showing synced, queued, processing and rejected files in real time
  • Rejection reasons stated in plain language
  • Per-destination mapping and storage inspection
  • Chat and webhook notifications for passes, rejections and corrections

Field fit

Who it is for — and where it stops

Built for

  • Video engineers and media server operators receiving content under time pressure
  • Content leads enforcing one spec across several creators
  • Production managers who need delivery status without asking for it
  • Shops running the same validation rules across repeat shows

Outside its authority

  • It validates and delivers — it does not play back or drive a show
  • It does not transcode content into spec on your behalf
  • It does not manage a media server's internal show state
  • It is a production-network tool, not a public content-distribution service
