The safe loop

Load the block, read the personality, hand the crew a document

The problem CueNotch addresses is a handoff problem: the person who built the Notch content knows what channel 63 does on layer two, and nobody else does until somebody retypes it into a spreadsheet.

  1. 01

    Load

    Open a Notch block file and extract its layers and exposed parameters.

  2. 02

    Map

    Resolve each parameter to its DMX channel, reading the file first and falling back to the personality template.

  3. 03

    Review

    Check the per-layer differences, annotate parameters, and compare against the previous version.

  4. 04

    Generate

    Produce the operator documentation and the fixture and profile outputs for the console.

  5. 05

    Hand off

    Share the generated document with the crew who have to run the show.

Capabilities

Built for the Notch-to-crew handoff

Read the block honestly

Layer-aware parameter extraction

The same effect slot can mean different things on different layers, and that difference is exactly what the crew needs written down.

  • Parameters extracted per layer and classified as effect, effect-colour or global
  • DMX channel read from the block file first, with a personality template filling gaps
  • Effect ranges and region labels enriched from the block's node graph
  • Authored parameters with no DMX channel hidden by default, with a toggle to show them

Give the crew a reference

Operator documentation

The output is a document people can actually work from, not a raw parameter dump.

  • Operator cheat sheet covering DMX channels, ranges and defaults
  • Backend view describing layer setup and signal flow
  • Node-graph view of the effect grid and group distribution
  • Self-contained documents that open on a laptop or a phone without extra software

Keep versions straight

Diffs, annotations and shows

Content changes between rehearsals; the documentation has to say what moved.

  • Parameter diff between block versions showing added, removed and changed entries
  • Version snapshots retained per block
  • Per-parameter notes and crew feedback captured against the document
  • Multi-block show aggregation for a whole production
  • Directory watching so a re-export can be picked up without reloading by hand

Feed the console

Fixture and profile outputs

Once the personality is understood, it should not have to be retyped into the lighting console.

  • MA fixture and profile output generation
  • Routing and screen-mapping definitions maintained alongside the block
  • Export as CSV, JSON, HTML and PDF
  • Spreadsheet push for teams still working from a shared sheet

Field fit

Who it is for — and what it does not claim

Built for

  • Notch programmers who currently maintain the personality sheet by hand
  • Media-server operators who need to know what each channel does
  • Lighting programmers importing the fixture into the console
  • Production crews who need one current reference rather than four stale ones

Stated limits

  • Block-file compatibility is still being validated; universal compatibility is not claimed
  • The local documentation view has no access control and is not intended for untrusted networks
  • It is not certified for unattended show operation
  • There is no public download and no signed customer distribution
  • It documents and generates; it does not drive DMX or control a show

Availability

Portfolio recognition, not a release

Private Validation — Not Publicly Released

CueNotch appears here because the work is real, not because it is for sale.

CueNotch is undergoing private compatibility and buyer validation. There is no public download, no purchase path, and no published price. Nothing on this page should be read as a release date or an availability commitment.

If you run Notch content on a show and maintain the personality reference by hand, that is exactly the workflow being validated — and it is worth a conversation.
