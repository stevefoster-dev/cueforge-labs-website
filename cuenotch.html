02

The handoff problem

One person knows what channel 63 does. Everyone else is guessing.

The person who built the Notch content knows what each exposed parameter means on each layer. Until CueNotch, the only way anyone else found out was retyping it into a spreadsheet — and the desk operator and the video director needed different halves of it. Underneath every one of those sheets is the same thing: a channel map that had to be read out of the block first.

Job — give the desk operator the channels

Every FX slot named, layer by layer

The operator sheet lists the per-song FX parameters the way the desk needs them: slot, DMX channel, console channel, range, default and what the slot actually does. These are the parameters that change song to song, and the sheet says so at the top rather than leaving the operator to find out during the set.

  • FX slots resolved to both their DMX channel and the console channel
  • Range and default printed beside every parameter
  • Layer filter, because the same slot number means different things per layer
  • Per-parameter flagging, so a wrong entry is marked where it was found

Boundary CueNotch documents and generates. It does not drive DMX or control a show.

Job — put every reader on the same block

One block in, a document for each person who needs one

The director sheet above and the operator sheet beside it are two outputs of a single extraction, and the hub is where that set is published. The crew documents and the programmer documents are generated together from the same block, so nobody is reading a version that stopped being true two exports ago.

  • Crew documents — operator sheet, layer snapshot, change dashboard, set list and director sheet
  • Programmer documents — layer setup and wiring notes, and the block's node graph
  • Block summary reporting layers, total parameters, exported parameters and FX parameters
  • Generated timestamp printed on the hub, so a stale document is visible as stale

Boundary Block-file compatibility is still being validated. Universal compatibility is not claimed, and the local documentation view has no access control.

All four images on this page are separate captures of the exact audited CueNotch runtime on a localhost-only machine. The director sheet, operator sheet and documentation hub are one session reading a synthetic three-layer validation block of 93 parameters; the Live Sheet above is a separate session reading a smaller synthetic 24-parameter block, which is why its counts differ. The documentation server served that machine and nothing else, and is shown stopped in the Live Sheet; the local documentation view has no access control and is not intended for untrusted networks. A local document server running is not public availability — CueNotch remains in private validation and is not publicly released.

03

The safe loop

Load the block, read the personality, hand the crew a document

Nothing is published to the room until a human has reviewed what the extraction produced.

  1. 01

    Load

    Open a Notch block file and extract its layers and exposed parameters.

  2. 02

    Map

    Resolve each parameter to its DMX channel, reading the file first and falling back to the personality template.

  3. 03

    Review

    Check the per-layer differences, annotate parameters, and compare against the previous version.

  4. 04

    Generate

    Produce the operator documentation and the fixture and profile outputs for the console.

  5. 05

    Hand off

    Share the generated document with the crew who have to run the show.

Built for

  • Notch programmers who currently maintain the personality sheet by hand
  • Media-server operators who need to know what each channel does
  • Lighting programmers importing the fixture into the console
  • Production crews who need one current reference rather than four stale ones

Stated limits

  • Block-file compatibility is still being validated; universal compatibility is not claimed
  • The local documentation view has no access control and is not intended for untrusted networks
  • It is not certified for unattended show operation
  • There is no public download and no signed customer distribution
  • It documents and generates; it does not drive DMX or control a show

04

Status

Portfolio recognition, not a release

Private Validation — Not Publicly Released

CueNotch appears here because the work is real, not because it is for sale.

CueNotch is undergoing private compatibility and buyer validation. There is no public download, no purchase path, and no published price. Nothing on this page should be read as a release date or an availability commitment.

If you run Notch content on a show and maintain the personality reference by hand, that is exactly the workflow being validated — and it is worth a conversation.
